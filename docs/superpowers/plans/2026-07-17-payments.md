# Payments (2b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Part B of the Event Bus & Payments spec — real Stripe Checkout and Vipps ePayment flows with signature-verified webhooks that update payment status, emit `payment.*` events on the bus, and move linked deals to won.

**Architecture:** `lib/payments.ts` becomes `lib/payments/` (index.ts preserves the existing `@/lib/payments` import path used by 3 files). Pure mapping logic (provider payload → internal `PaymentEventInput`) is TDD'd; provider modules (stripe.ts, vipps.ts) wrap the external APIs; one DB-layer `applyPaymentEvent` owns status transitions + bus emission + deal-won. Public checkout endpoint is session-gated and ownership-checked; webhook endpoints verify signatures BEFORE reading anything else. Unconfigured environments degrade cleanly (503 `Betaling er ikke konfigurert`) — dev has no secret keys.

**Tech Stack:** Next.js 16 App Router, Prisma 5, Zod 4, Vitest, `stripe` npm SDK (added in Task 2), Vipps MobilePay ePayment API v1 (plain fetch, no SDK), existing lib/events bus.

**Spec:** `docs/superpowers/specs/2026-07-16-event-bus-payments-design.md` (Part B)
**Flagged scope decision:** checkout UI is wired into the course signup flow (pamelding) only. Bookings (venue-event requests) go through admin approval first, so the API accepts `bookingRequestId` but no booking UI calls it yet — payment links for approved bookings are a later subproject. This deviates from a literal reading of the spec's "registration/booking" flow sentence and is approved.

## Global Constraints

- pnpm, never npm. Dev server: never port 3000 (use 3001).
- Prisma conventions as before; `pnpm prisma db push`; production SQL script in final task.
- Secrets ONLY via env: `STRIPE_SECRET_KEY`, `STRIPE_SECRET_KEY_TEST`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_WEBHOOK_SECRET_TEST`, `VIPPS_CLIENT_ID`, `VIPPS_CLIENT_SECRET`, `VIPPS_SUBSCRIPTION_KEY`, `VIPPS_MSN`, `VIPPS_WEBHOOK_SECRET`, `VIPPS_TEST_MODE`. Never log secrets; never put card/account data in our DB — provider refs and amounts only.

- API hardening pattern (guards → 400, P2025/P2003 → 404, P2002 → 409, guarded JSON) for the checkout route; UI hardening pattern for any UI touches.
- UI copy Norwegian (bokmål). Pages: `/betaling/takk`, `/betaling/avbrutt`.

```ts
export interface PaymentEventInput {
  type: 'payment.succeeded' | 'payment.failed' | 'payment.refunded';
  provider: 'stripe' | 'vipps';
  ref: string;
  refKind: 'paymentRef' | 'metadata';
  nextRef?: string;
  registrationId?: number;
  bookingRequestId?: number;
  amountKr: number | null;
  eventId: string;
}

const num = (v: unknown): number | null => (typeof v === 'number' ? v : null);
const idFromMeta = (meta: unknown, key: string): number | undefined => {
  if (typeof meta !== 'object' || meta === null) return undefined;
  const raw = (meta as Record<string, unknown>)[key];
  const n = Number(raw);
  return Number.isInteger(n) && n > 0 ? n : undefined;
};

export function mapStripeEvent(event: { id: string; type: string; data: { object: Record<string, unknown> } }): PaymentEventInput | null {
  const o = event.data.object;
  if (event.type === 'checkout.session.completed') {
    const amount = num(o.amount_total);
    return {
      type: 'payment.succeeded', provider: 'stripe',
      ref: String(o.id), refKind: 'paymentRef',
      nextRef: typeof o.payment_intent === 'string' ? o.payment_intent : undefined,
      registrationId: idFromMeta(o.metadata, 'registrationId'),
      bookingRequestId: idFromMeta(o.metadata, 'bookingRequestId'),
      amountKr: amount !== null ? amount / 100 : null,
      eventId: event.id,
    };
  }
  if (event.type === 'payment_intent.payment_failed') {
    const amount = num(o.amount);
    return {
      type: 'payment.failed', provider: 'stripe',
      ref: String(o.id), refKind: 'metadata',
      registrationId: idFromMeta(o.metadata, 'registrationId'),
      bookingRequestId: idFromMeta(o.metadata, 'bookingRequestId'),
      amountKr: amount !== null ? amount / 100 : null,
      eventId: event.id,
    };
  }
  if (event.type === 'charge.refunded') {
    const amount = num(o.amount_refunded);
    if (typeof o.payment_intent !== 'string') return null;
    return {
      type: 'payment.refunded', provider: 'stripe',
      ref: o.payment_intent, refKind: 'paymentRef',
      amountKr: amount !== null ? amount / 100 : null,
      eventId: event.id,
    };
  }
  return null;
}

const VIPPS_MAP: Record<string, PaymentEventInput['type']> = {
  AUTHORIZED: 'payment.succeeded',
  CAPTURED: 'payment.succeeded',
  FAILED: 'payment.failed',
  EXPIRED: 'payment.failed',
  CANCELLED: 'payment.failed',
  TERMINATED: 'payment.failed',
  REFUNDED: 'payment.refunded',
};

export function mapVippsEvent(body: Record<string, unknown>): PaymentEventInput | null {
  const reference = typeof body.reference === 'string' ? body.reference : null;
  const name = typeof body.name === 'string' ? body.name : typeof body.eventName === 'string' ? body.eventName : null;
  if (!reference || !name) return null;
  const type = VIPPS_MAP[name];
  if (!type) return null;
  const amountValue = typeof body.amount === 'object' && body.amount !== null ? num((body.amount as Record<string, unknown>).value) : null;
  return {
    type, provider: 'vipps', ref: reference, refKind: 'paymentRef',
    amountKr: amountValue !== null ? amountValue / 100 : null,
    eventId: `${reference}:${name}`,
  };
}
```

### Task 7: `POST /api/payments/checkout`

**Files:**
- Create: `app/api/payments/checkout/route.ts`

**Interfaces:**

- Produces: `POST /api/payments/checkout` body `{ registrationId?: number; bookingRequestId?: number; provider: 'stripe' | 'vipps' }` (exactly one id, Zod-refined). Flow:
  1. Session required → 401. Guarded JSON → 400. Zod → 400.
  2. Load the row incl. course (+ parent.user for registrations). Not found → 404. OWNERSHIP: registration's `parent.user.email` must equal session email (bookings: `email` field equals session email) → else 403.
  3. Course `paymentMethods` must include the provider → 400 `{ error: 'Betalingsmetoden er ikke aktivert for dette arrangementet' }`. Amount: registration → `course.price`; booking → `course.price * participants` if those fields exist (mirror `lib/crm/bridge-mapping.ts`'s value rules); null/0 amount → 400 `{ error: 'Arrangementet har ingen pris' }`.
  4. Provider unconfigured → 503 `{ error: 'Betaling er ikke konfigurert' }`.
  5. Create session: Stripe → `createStripeCheckout` (success `${origin}/betaling/takk?ref={ref}`, cancel `${origin}/betaling/avbrutt`); Vipps → `createVippsPayment` with `reference` = `reg-{id}-{random 8 hex}` / `book-{id}-{...}` and returnUrl `${origin}/betaling/takk?ref={reference}`. Origin from `request.nextUrl.origin`.
  6. Persist `paymentRef`/`paymentProvider`/`paymentStatus: 'pending'` on the row (P2002 on paymentRef → 409). Return `{ url }`.
  7. `logActivity({ action: 'checkout_started', entity, entityId, userEmail: session.user.email }).catch(() => {})`.
